# 分阶段执行方案

## 总体执行原则

项目方向已经调整为全局对话式 Agent + LLM planner + 工具调用。

推进原则：

- 先更新文档和阶段目标，再继续实现。
- Agent 是全局入口，不是工作流页面助手。
- Planner 模型在 Agent 窗口内选择，不新增全局设置项。
- LLM planner 负责规划，Runtime 负责校验和执行。
- 工作流是工具，不是 Agent 的唯一能力。
- 每个高成本或有副作用的工具都必须有确认机制。
- React Flow 状态仍由 React Flow 管理，不能进入 Zustand。
- 本地 MVP 优先覆盖 `desktop` 和 `local-web`。

## 阶段 0：方向重置与文档落地

目标：

把旧的“AI 设计团队 / 工作流助手”路线调整为“对话式 Agent / LLM planner / 工具调用”路线。

范围：

- 更新总计划、阶段计划、验收计划。
- 将 `05-设计团队与工作流自动搭建方案.md` 替换为 `05-对话式Agent与工具规划方案.md`。
- 明确旧团队模板不再是当前主线。
- 明确 Planner 模型选择放在 Agent 窗口内。
- 保留知识库、Skills、工作流 builder 的可复用成果。

不做：

- 不改运行时代码。
- 不新增后端接口。
- 不开始 LLM planner 实现。

验收：

```bash
npm run check:encoding
```

人工验收：

- 文档不再把“设计团队”作为第一版主入口。
- 文档明确工作流只是 Agent 工具之一。
- 文档明确下一阶段是 Agent 窗口内模型选择和 LLM planner。

## 阶段 1：全局 Agent UI 基线

目标：

把原工作流工具栏的 `AI 助手` 按钮接到全局 Agent 窗口，并移除旧工作流助手主路径。

范围：

- `src/features/agent/` 承载全局 Agent 窗口。
- 工作流页只提供打开 Agent 的入口。
- Agent 窗口展示对话、最终结果、折叠工具记录。
- 旧工作流助手、旧草案执行面板不再挂载。

验收：

- 点击工作流工具栏 `AI 助手` 打开 `AI Agent` 窗口。
- 前端不再出现 `AI 工作流助手` 或 `AI 设计团队` 主标题。
- 工具记录默认折叠。
- `npm run typecheck`
- `npm run check:encoding`
- `npm run build`

## 阶段 2：Agent 窗口内 Planner 模型选择

目标：

让用户直接在 Agent 窗口选择 LLM planner 使用的对话模型。

范围：

- Agent 窗口读取已显式启用的 `chat` 类模型。
- 显示当前 Planner 模型。
- 支持切换 Planner 模型。
- 本地记住最近选择。
- 没有可用对话模型时提示用户先启用模型。

规则：

- 不新增全局设置项。
- 不自动使用图像或视频模型。
- 不使用首次发现但未启用的模型。
- 不绕过现有 provider 配置和用户启用规则。

验收：

- 有多个对话模型时可以在 Agent 窗口切换。
- 没有对话模型时，Agent 不调用 planner，并给出明确提示。
- 切换模型后下一次 planner 调用使用新模型。

## 阶段 3：LLM Planner MVP

目标：

接入真正的 LLM planner，让 Agent 不再只依赖本地硬编码规则来决定工作流结构。

新增后端能力：

```text
POST /api/intelligence/agent/plans
```

输入：

```text
用户需求
Planner 模型配置引用
当前页面/工作流上下文
可用工具列表
可用节点知识
相关知识检索结果
```

输出：

```text
AgentPlan
  goal
  clarificationQuestions
  steps[]
  finalResponseHint
```

规则：

- LLM 输出必须经过 Zod 校验。
- Planner 只能输出计划，不能直接修改画布。
- Planner 不能直接执行高成本工具。
- 计划中的工具必须存在于 Tool Registry。

验收案例：

```text
用户：帮我做一个分镜图生成流程，用文本脚本生成 8 张连续分镜图。
```

期望：

- Planner 识别这是图像序列/分镜图任务。
- 不直接选择视频生成节点。
- 能选择文本输入、拆分/逐项、图像生成、保存/输出等合理工具或节点。
- 信息不足时先追问。

## 阶段 4：Tool Runtime 与工作流工具化

目标：

把工作流能力正式变成 Agent 可调用工具，而不是独立工作流助手逻辑。

第一批工具：

```text
workflow.inspect
workflow.createDraft
workflow.validate
workflow.suggestInputs
workflow.execute
workflow.diagnose
workflow.summarizeRun
```

阶段 6 预留工具：

```text
workflow.edit
workflow.applyDraft
```

规则：

- `workflow.createDraft` 可以自动生成草案，但不能自动应用。
- `workflow.applyDraft` 在阶段 6 落地草案或 patch 应用时必须用户确认。
- `workflow.execute` 必须用户确认。
- `workflow.edit` 在阶段 6 引入时必须基于当前画布上下文和可验证 patch。
- 所有工具调用写入 trace。

验收：

- Agent 可以通过 LLM planner 选择 `workflow.createDraft`。
- 生成的草案能通过现有 compiler/validator。
- 用户点确认后新建画布。
- 工具调用记录能展开查看。

## 阶段 5：节点语义知识与工作流规划质量提升

目标：

解决“节点语义不准确导致 planner 选错节点”的问题。

范围：

- 建立节点语义知识 schema。
- 每个节点记录真实用途、输入输出、适用场景、不适用场景、典型组合。
- 特别校准：
  - 辅助提示词
  - 逐项运行
  - 合并节点
  - 视频生成
  - 图像生成
  - AI 对话
  - 保存文件
  - 输出展示
- Planner 调用前检索节点知识。
- 规划结果记录命中的节点知识。

验收：

- 分镜图任务不误用视频生成节点。
- 简单直连输入输出任务不强行加入辅助提示词。
- 多输入、多输出、逐项、合并场景能给出合理结构。
- 用户能通过前端实际测试发现 planner 行为变化。

## 阶段 6：工作流编辑、运行、诊断闭环

目标：

让 Agent 不只是新建工作流，还能操作已有工作流。

范围：

- 读取当前画布。
- 根据用户要求生成编辑计划。
- 应用可验证的节点/连线/参数 patch。
- 执行工作流。
- 读取运行结果和产物。
- 诊断失败节点。
- 输出结果报告。

验收：

- 用户可以说“把这个工作流改成生成 6 张图”。
- Agent 能生成可确认的修改方案。
- 确认后画布更新。
- 运行失败时 Agent 能定位失败节点并总结原因。

## 阶段 7：生产工具扩展

目标：

把图像、视频、文本、提示词、文件、资产能力接入同一套 Agent 工具系统。

工具：

```text
image.generate
image.edit
image.compare
video.generate
copy.write
prompt.optimize
asset.package
asset.index
result.inspect
```

验收：

- Agent 可以不经过工作流，直接调用图像或文本工具完成简单任务。
- 高成本生成默认需要确认。
- 结果能在 Agent 中展示，并能进入现有结果查看逻辑。
- 产物 URL 使用现有 `/api/outputs/...` 规则。

## 阶段 8：Studio Brain 知识库增强

目标：

让 Planner 越用越准。

范围：

- 用户偏好。
- 节点语义。
- 工具使用经验。
- 模型能力经验。
- 成功工作流模板。
- 失败运行经验。
- 产物和结果索引。

规则：

- 重要规则写入需要确认。
- 运行经验必须来自真实 trace。
- 不写入 chain-of-thought。
- 不写入大 base64 或绝对路径。

验收：

- 相似任务能推荐历史成功结构。
- 失败经验能影响下一次规划。
- 知识命中能在工具记录中折叠查看。

## 阶段 9：旧 Agent 与旧工作流助手切换

目标：

让主流程完全切到新对话式 Agent。

范围：

- `/api/agent` 标记 deprecated 或缩成兼容层。
- 旧 Agent Profile 不再承担主流程。
- 旧工作流助手组件删除。
- Settings 不再管理“团队模板”作为主入口。
- Workflow 主流程复用新 Agent 工具系统；旧 Chat 页不再作为独立入口保留。

验收：

```bash
npm run check
```

人工验收：

- 主流程入口是全局 Agent。
- 工作流页没有独立工作流助手。
- 用户可以通过 Agent 完成至少一条工作流生成和运行路径。

## 阶段 10：本地模板化与复盘增强

目标：

把成功计划、工具调用、工作流和产物沉淀为可复用模板。

范围：

- 成功工作流建议保存为模板。
- 成功提示词保存为 prompt pack。
- 成功工具计划保存为 task pattern。
- 失败诊断保存为 run knowledge。

验收：

- 重复任务能推荐历史模板。
- 用户能确认保存模板。
- 模板复用不绕过确认和校验。
