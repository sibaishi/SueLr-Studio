# 分阶段执行方案

## 总体执行原则

整个计划必须分阶段推进，不能一次性重写。

每个阶段都要保证：

- App 仍然可用
- 当前旧 Agent API 在切换前继续可用
- 先加新模块，再逐步替换旧模块
- 后端输入必须 Zod 校验
- 错误响应保持 `{ error, code, status }`
- 工作流执行继续走现有 `ExecutionService`
- 运行时文件继续走 storage resolver
- 中文文本保持 UTF-8
- 每个阶段都有明确验收标准

## 阶段 0：基线治理与文档落地

目标：

先把方向、门禁、现状和风险固定下来。

范围：

- 落地公开规划文档
- 修改 docs 门禁，允许 `docs/intelligence/`
- 明确旧 Agent 体系是 legacy
- 盘点当前 Agent、Memory、Tool、Workflow 执行代码
- 修复或登记中文乱码问题

不做：

- 不替换运行时
- 不改 UI 交互
- 不改模型调用

验收：

```bash
npm run check:docs
npm run check:encoding
```

## 阶段 1：新 Intelligence Runtime 骨架

目标：

建立一个并行的新后端智能模块，不影响旧 Agent。

新增目录：

```text
backend/src/modules/intelligence/
  intelligence.routes.ts
  intelligence.controller.ts
  intelligence.schema.ts
  runtime/
  skills/
  knowledge/
  agents/
```

第一批只读 Skills：

```text
knowledge.search
workflow.list
workflow.inspect
model.list
```

第一批 API：

```text
POST /api/intelligence/runs
GET  /api/intelligence/runs/:id
GET  /api/intelligence/skills
GET  /api/intelligence/knowledge
```

验收：

- 新 API 可用
- 旧 `/api/agent` 不受影响
- run trace 可保存和读取
- 只读 Skills 不能产生副作用

## 阶段 2：Workflow Architect MVP

目标：

让 Agent 能根据需求生成工作流草案，但不自动保存、不自动执行。

新增：

```text
workflow-builder/
  workflow-intent.schema.ts
  workflow-draft.schema.ts
  workflow-compiler.ts
  workflow-validator.ts
```

新增 Skills：

```text
brief.parse
workflow.plan
workflow.createDraft
workflow.validate
```

前端入口：

```text
src/domains/workflow/
  工作流 AI 助手
  草案预览
  应用草案确认
```

验收例子：

用户输入：

```text
帮我做一个商品图生成工作流，输入产品图和一句卖点，输出 6 张不同风格的电商主图。
```

系统输出：

```text
Image Input
Text Input
Prompt Helper / AI Chat
Image Gen x 6
Image Compare / Review
Save File
Output
```

要求：

- 用户能预览
- 用户确认后才能应用
- React Flow 状态仍由 React Flow 管

## 阶段 3：工作流执行闭环

目标：

用户确认后，智能系统能执行工作流、诊断失败、总结结果。

新增 Skills：

```text
workflow.execute
workflow.diagnose
workflow.suggestInputs
workflow.summarizeRun
```

规则：

- 执行必须走现有 `ExecutionService`
- 工作流目标必须来自当前请求或用户明确确认
- 输入覆盖必须来自当前请求或用户明确确认
- 知识库只能提供建议，不能静默执行

验收：

- 草案可保存并执行
- 执行失败能给出节点级诊断
- 执行成功能输出资产列表和运行报告
- 断开 SSE 不等于取消
- 显式取消仍走现有 cancel endpoint

## 阶段 4：Studio Brain 知识库 MVP

目标：

把简单 Memory 升级成细分类知识库。

第一版 JSON 文件：

```text
knowledge/user-memory.json
knowledge/project-knowledge.json
knowledge/brand-knowledge.json
knowledge/workflow-knowledge.json
knowledge/asset-knowledge.json
knowledge/run-knowledge.json
knowledge/prompt-library.json
knowledge/model-knowledge.json
```

新增 Skills：

```text
knowledge.search
knowledge.write
knowledge.linkAsset
knowledge.summarizeRun
knowledge.extractPreference
knowledge.promoteToTemplate
```

验收：

- 知识记录有类型、来源、作用域、证据
- 运行经验必须来自真实 run trace
- 品牌规则、项目规则写入前需要确认
- 旧 memory 可以迁移或导入

## 阶段 5：设计团队 MVP

目标：

引入多角色团队，但先用可控的项目经理调度制。

新增：

```text
teams/team-orchestrator.ts
teams/team-template.service.ts
agents/role-runner.ts
planner/project-plan.service.ts
review/review.service.ts
```

第一批团队：

```text
品牌视觉团队
工作流工程团队
电商素材团队
```

协作模式：

```text
串行生产
并行提案
评审返工
```

验收：

- 项目经理能拆任务
- 创意总监能评审方向
- Workflow Architect 能出工作流草案
- 质检角色能打分
- 每个角色输出都有 trace

## 阶段 6：资产生产流水线扩展

目标：

把图片、视频、文案、提示词、资产包都纳入 Skills。

新增 Skills：

```text
prompt.optimize
prompt.variant
copy.write
image.generate
image.edit
image.compare
video.generate
asset.package
asset.index
```

规则：

- 图片/视频继续复用现有 provider 和输出路径
- 不把大 base64 写进日志或知识库
- 高成本生成默认需要确认

验收：

- 团队计划能调用生产 Skills
- 资产能在结果面板看到
- 资产能写入素材知识库

## 阶段 7：旧 Agent 默认切换

目标：

把聊天、设置、工作流助手逐步切到新 Intelligence Runtime。

范围：

- Chat 使用新 runtime
- Settings 管理新 Agent、Team、Skill、Knowledge
- 旧 Memory 迁移到 typed knowledge
- `/api/agent` 标记 deprecated
- 最后删除或缩成兼容层

验收：

- 旧能力有新能力覆盖
- 前端不再依赖旧 `src/shared/api/agent.ts`
- 后端旧 Agent 测试迁移完成
- `npm run check` 通过

## 阶段 8：高级自动化与模板化

目标：

让系统越用越强。

能力：

- 成功工作流自动建议保存模板
- 成功提示词沉淀为 prompt pack
- 成功团队配置保存为 team template
- 按需求推荐历史工作流
- 可选 SQLite
- 可选 embedding 检索

验收：

- 重复任务能推荐历史模板
- 用户能一键复用团队 + 工作流 + 提示词组合
- 知识库能提升规划质量，但不能绕过审批
