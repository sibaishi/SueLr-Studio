# 知识库分类与治理方案

## 总目标

知识库要成为 SueLr Studio 的 Studio Brain。

它不是简单记忆，也不是一堆向量片段，而是结构化、可追溯、可治理、能服务设计生产的长期知识系统。

## 存储演进

第一阶段：JSON

```text
knowledge/
  user-memory.json
  project-knowledge.json
  brand-knowledge.json
  design-system-knowledge.json
  workflow-knowledge.json
  skill-knowledge.json
  model-knowledge.json
  prompt-library.json
  asset-knowledge.json
  run-knowledge.json
  review-knowledge.json
  team-knowledge.json
  template-knowledge.json
  domain-knowledge.json
  safety-knowledge.json
```

第二阶段：SQLite

```text
knowledge/studio-brain.db
```

第三阶段：Embedding

只有在结构化记录、来源、权限、迁移都稳定后，再引入本地 embedding 检索。

不建议第一版就上外部向量数据库。

## 通用知识记录结构

每条知识至少包含：

```text
id
type
scope
title
content
structured
tags
source
confidence
evidence
createdAt
updatedAt
ownerUserId
workspaceId
ownershipScope
```

## 详细分类

### 1. User Memory 用户记忆

记录：

- 用户偏好
- 语言习惯
- 常用风格
- 不喜欢的输出方式
- 常用交付格式

写入规则：

- 明确、低风险偏好可自动写入
- 模糊偏好要确认
- 临时任务信息不要写入

### 2. Project Knowledge 项目知识

记录：

- 项目目标
- 客户背景
- 交付清单
- 预算/周期
- 当前决策
- 项目约束

写入规则：

- 关键项目决策要确认
- 过期项目上下文要能归档

### 3. Brand Knowledge 品牌知识

记录：

- 品牌定位
- 目标用户
- 品牌语气
- 色彩
- 字体
- 视觉风格
- 竞品
- 禁用风格

写入规则：

- 品牌规则必须确认
- AI 生成的品牌建议只是候选

### 4. Design System Knowledge 设计系统知识

记录：

- UI 组件规则
- 间距
- 字号
- 色彩 token
- 页面密度
- 交互规范

写入规则：

- 最好来源于代码、设计稿或用户确认

### 5. Workflow Knowledge 工作流知识

记录：

- 工作流用途
- 输入要求
- 节点说明
- 适用场景
- 常见失败
- 推荐模型

写入规则：

- 运行建议必须来自真实执行证据

### 6. Skill Knowledge 能力知识

记录：

- Skill 何时使用
- 参数经验
- 重试策略
- 失败特征
- 成本风险

写入规则：

- 来自 trace 或维护者输入

### 7. Model Knowledge 模型知识

记录：

- 模型能力
- 适合任务
- 上下文限制
- 图片/视频能力
- 稳定参数
- 已知问题

写入规则：

- 模型发现不等于可用
- 能力结论要有 discovery 或 run evidence

### 8. Prompt Library 提示词库

记录：

- 成功提示词
- 失败提示词
- 风格提示词
- 镜头提示词
- 负面提示词
- 品牌提示词片段

写入规则：

- 成功提示词要关联产物
- 失败提示词要记录失败原因

### 9. Asset Knowledge 素材知识

记录：

- 上传素材
- 生成图片
- 生成视频
- 音频
- 文件
- 风格标签
- 可复用程度

写入规则：

- 只存相对 URL 或存储标识
- 不存绝对路径

### 10. Run Knowledge 运行知识

记录：

- 输入摘要
- 使用工作流
- 使用模型
- 输出
- 错误
- 耗时
- 重试次数
- 评分

写入规则：

- 必须来自真实 run trace

### 11. Review Knowledge 评审知识

记录：

- 评分
- 评审标准
- 拒绝原因
- 通过原因
- 返工建议

写入规则：

- 要关联评审角色、标准、产物

### 12. Team Knowledge 团队知识

记录：

- 团队模板
- 角色配置
- 协作方式
- 任务拆分策略

写入规则：

- 自定义团队需要用户保存

### 13. Template Knowledge 模板知识

记录：

- 项目模板
- 工作流模板
- 提示词包
- 交付模板

写入规则：

- 需要用户确认保存

### 14. Domain Knowledge 领域知识

记录：

- 品牌方法论
- 电商设计经验
- 社媒内容经验
- 视频创作经验
- 包装设计经验
- UI/UX 经验

写入规则：

- 要区分通用知识和项目规则

### 15. Safety Knowledge 安全知识

记录：

- 版权风险
- 敏感内容
- 禁用宣称
- 外部调用限制
- 删除/覆盖策略

写入规则：

- 高敏感记录需要明确来源和确认

## 检索结果要求

检索返回不能只给文本，要包含：

- 类型
- 相关度
- 来源
- 置信度
- 更新时间
- 治理说明

## 写入治理

自动写入允许：

- 明确偏好
- 低风险标签
- 有 trace 的运行摘要
- 用户明确保存的提示词

必须确认：

- 品牌规则
- 项目约束
- 工作流模板
- 模型偏好
- 删除或覆盖
- 未来会影响生产行为的重要知识

禁止写入：

- 原始 chain-of-thought
- 大 base64
- 临时 debug 噪音
- 堆栈错误当成用户记忆
- 绝对文件路径
- 未确认的品牌规则
