# 知识库分类与治理方案

## 总目标

知识库要成为 LLM planner 和工具调度的长期上下文，不是简单记忆，也不是固定团队模板库。

它的核心价值是让 Agent 更准确地理解：

- 用户偏好。
- 当前项目目标。
- 节点真实语义。
- 工具何时使用。
- 模型适合什么任务。
- 历史成功工作流。
- 失败运行经验。
- 产物和素材上下文。

知识库默认是 `desktop` 和 `local-web` 的本地个人/项目知识库。

## 存储演进

第一阶段：JSON

```text
knowledge/
  user-memory.json
  project-knowledge.json
  brand-knowledge.json
  node-knowledge.json
  tool-knowledge.json
  workflow-knowledge.json
  model-knowledge.json
  prompt-library.json
  asset-knowledge.json
  run-knowledge.json
  review-knowledge.json
  template-knowledge.json
  domain-knowledge.json
  safety-knowledge.json
```

第二阶段：SQLite

```text
knowledge/studio-brain.db
```

第三阶段：Embedding

只有在结构化记录、来源、权限、迁移都稳定后，再引入本地 embedding 检索。

## 通用知识记录结构

每条知识至少包含：

```text
id
type
scope
title
content
structured
tags
source
confidence
evidence
createdAt
updatedAt
sourceRuntime
version
syncStatus
```

`sourceRuntime`、`version`、`syncStatus` 用于保持记录来源、版本和本地同步状态。`scope` 只表示本地私有或本地项目知识，不承载多用户归属。

## 详细分类

### 1. User Memory 用户记忆

记录：

- 用户偏好。
- 常用语言。
- 输出格式偏好。
- 不喜欢的表现形式。
- 常用交付物类型。

治理：

- 明确、低风险偏好可自动写入。
- 模糊偏好需要确认。
- 临时任务信息不要写入长期记忆。

### 2. Project Knowledge 项目知识

记录：

- 项目目标。
- 客户背景。
- 交付清单。
- 预算/周期。
- 当前决策。
- 项目约束。

治理：

- 关键项目决策写入前需要确认。
- 过期上下文要能归档。

### 3. Brand Knowledge 品牌知识

记录：

- 品牌定位。
- 目标用户。
- 品牌语气。
- 色彩。
- 字体。
- 视觉风格。
- 竞品。
- 禁用风格。

治理：

- 品牌规则必须确认。
- AI 生成的品牌建议只是候选。

### 4. Node Knowledge 节点知识

这是 LLM planner 能否正确搭建工作流的关键知识。

每个节点要记录：

- 节点类型。
- 真实用途。
- 输入端口。
- 输出端口。
- 参数含义。
- 适用场景。
- 不适用场景。
- 常见上游节点。
- 常见下游节点。
- 常见误用。
- 典型组合。

重点校准：

- 辅助提示词。
- 文本逐项。
- 图像逐项。
- 文本合并。
- 图片合并。
- 视频合并。
- 音频合并。
- AI 对话。
- 图像生成。
- 视频生成。
- 保存文件。
- 输出展示。

治理：

- 节点语义必须以真实节点实现和用户审核为准。
- 不能靠节点名称猜用途。
- 用户修正过的节点语义优先级高于自动推断。

### 5. Tool Knowledge 工具知识

记录：

- Tool/Skill 何时使用。
- 输入 schema。
- 输出 schema。
- 副作用等级。
- 是否需要确认。
- 参数经验。
- 重试策略。
- 失败特征。
- 成本风险。

治理：

- 来自 trace 或维护者输入。
- 高成本工具必须标明确认规则。

### 6. Workflow Knowledge 工作流知识

记录：

- 工作流用途。
- 输入要求。
- 节点组合模式。
- 适用场景。
- 常见失败。
- 推荐模型。
- 成功案例。

治理：

- 运行建议必须来自真实执行证据或用户确认。
- 工作流模板保存需要用户确认。

### 7. Model Knowledge 模型知识

记录：

- 模型能力。
- 适合任务。
- 不适合任务。
- 上下文限制。
- 图像/视频能力。
- 稳定参数。
- 已知问题。

治理：

- 模型发现不等于可用。
- Planner 只能使用用户已显式启用的对话模型。
- 能力结论需要 discovery 或 run evidence。

### 8. Prompt Library 提示词库

记录：

- 成功提示词。
- 失败提示词。
- 风格提示词。
- 镜头提示词。
- 负面提示词。
- 品牌提示词片段。

治理：

- 成功提示词要关联产物。
- 失败提示词要记录失败原因。

### 9. Asset Knowledge 素材知识

记录：

- 上传素材。
- 生成图片。
- 生成视频。
- 音频。
- 文件。
- 风格标签。
- 可复用程度。

治理：

- 只存相对 URL 或存储标识。
- 不存绝对路径。
- 缩略图不应作为最终产物知识单独沉淀。

### 10. Run Knowledge 运行知识

记录：

- 输入摘要。
- 使用工具。
- 使用工作流。
- 使用模型。
- 输出。
- 错误。
- 耗时。
- 重试次数。
- 诊断结论。

治理：

- 必须来自真实 run trace。
- 不写入原始 chain-of-thought。

### 11. Review Knowledge 评审知识

记录：

- 评分。
- 评审标准。
- 拒绝原因。
- 通过原因。
- 返工建议。

治理：

- 要关联产物、评审标准和来源。

### 12. Template Knowledge 模板知识

记录：

- 任务计划模板。
- 工作流模板。
- 工具调用模式。
- 提示词包。
- 交付模板。

治理：

- 需要用户确认保存。
- 模板复用不能绕过 planner 校验和用户确认。

### 13. Domain Knowledge 领域知识

记录：

- 品牌方法论。
- 电商设计经验。
- 社媒内容经验。
- 视频创作经验。
- 包装设计经验。
- UI/UX 经验。

治理：

- 要区分通用知识和项目规则。

### 14. Safety Knowledge 安全知识

记录：

- 版权风险。
- 敏感内容。
- 禁用宣称。
- 外部调用限制。
- 删除/覆盖策略。

治理：

- 高敏感记录需要明确来源和确认。

## 检索结果要求

检索返回不能只给文本，要包含：

- 类型。
- 相关度。
- 来源。
- 置信度。
- 更新时间。
- 治理说明。
- 是否来自用户确认。

## 写入治理

自动写入允许：

- 明确偏好。
- 低风险标签。
- 有 trace 的运行摘要。
- 用户明确保存的提示词。

必须确认：

- 品牌规则。
- 项目约束。
- 工作流模板。
- 工具调用模板。
- 模型偏好。
- 删除或覆盖。
- 会影响后续生产行为的重要知识。

禁止写入：

- 原始 chain-of-thought。
- 大 base64。
- 临时 debug 噪声。
- 堆栈错误当成用户记忆。
- 绝对文件路径。
- 未确认的品牌规则。
