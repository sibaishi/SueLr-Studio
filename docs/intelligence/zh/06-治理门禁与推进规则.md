# 治理门禁与推进规则

## 公开文档规则

长期有效的产品方案、架构方案、执行计划和验收计划允许放在：

```text
docs/intelligence/
docs/intelligence/zh/
```

不要放：

- 临时草稿。
- 私人笔记。
- 未定方案。
- 每周随手记录。

## 代码归属规则

后端新智能体系：

```text
backend/src/modules/intelligence/
```

前端：

```text
src/features/agent/       全局 Agent
src/domains/workflow/     工作流领域
src/features/settings/    设置
```

图像和视频生成作为 Agent 与 Workflow 工具能力保留，不再作为独立前端页面领域维护。

禁止把领域组件放进：

```text
src/components/
```

## Agent 治理规则

Agent 必须遵守：

- 用户通过对话提出需求。
- Planner 模型由用户在 Agent 窗口内选择。
- 只能使用用户显式启用的对话模型作为 Planner。
- LLM planner 只产出结构化计划。
- Runtime 校验计划后才能调用工具。
- 工具调用默认折叠展示。
- 最终结果优先展示给用户。

禁止：

- 把 Agent 固定成工作流页面助手。
- 把“设计团队模板”作为第一版主入口。
- 自动使用图像/视频模型做 Planner。
- 使用未启用的发现模型。
- 暴露原始 chain-of-thought。

## 工作流安全规则

禁止：

- 模型直接修改 React Flow 状态。
- 模型直接写最终工作流 JSON 并落库。
- 未确认就执行生成的工作流。
- 知识库静默选择工作流。
- 知识库静默填写工作流输入。

必须：

```text
用户需求
  -> AgentPlan
  -> WorkflowDraft
  -> 编译
  -> 校验
  -> 预览
  -> 用户确认
  -> 应用、保存或执行
```

## 本地 MVP 门禁

第一实现门禁是 `desktop` 和 `local-web` 的完整本地闭环：

- Agent 窗口能选择 Planner 模型。
- LLM planner 能生成结构化计划。
- Tool Runtime 能校验并执行受控工具。
- Workflow tools 能在本地创建、校验、应用和执行草案。
- Studio Brain 默认使用本地个人/项目知识。
- 资产输出继续使用现有 App URL 协议。
- 旧 Agent 替换先在本地验收完成。

这个门禁通过前，不引入非本地运行形态作为实现前置条件。

## 知识库治理规则

每条知识必须有：

- 类型。
- 来源。
- 作用域。
- 置信度或证据。
- 创建/更新时间。

禁止写入：

- 原始 chain-of-thought。
- 大 base64。
- 临时 debug 噪声。
- 绝对文件路径。
- 未确认的品牌规则。
- 未确认的项目约束。

## Skill / Tool 治理规则

每个 Skill/Tool 必须定义：

- 输入 schema。
- 输出 schema。
- 副作用等级。
- 是否需要确认。
- 超时或取消策略。
- 日志策略。

副作用等级：

```text
read          只读
suggest       只建议
writeDraft    写草案
write         持久写入
execute       执行任务
external      外部调用
destructive   删除/覆盖
```

默认确认：

- `read`：不需要。
- `suggest`：不需要。
- `writeDraft`：生成草案不需要，应用草案需要。
- `write`：一般需要。
- `execute`：默认需要。
- `external`：需要用户开启或确认。
- `destructive`：必须确认。

## 校验命令

文档变更：

```bash
npm run check:docs
npm run check:encoding
```

后端智能模块变更：

```bash
npm run typecheck
npm run test --prefix backend
npm run check:encoding
```

前端 Agent UI 变更：

```bash
npm run typecheck
npm run test:unit
npm run build
```

重大切换前：

```bash
npm run check
```

## 推进主分支前检查

推进主分支前必须确认：

- 当前工作区没有未解释的用户改动。
- 文档门禁通过。
- 编码检查通过。
- 新增文档在允许目录。
- 没有修改 Electron CommonJS 规则。
- 没有改端口。
- 没有硬编码运行时路径。
- 没有把 React Flow 状态移入 Zustand。
- 没有把领域组件放进 `src/components/`。
