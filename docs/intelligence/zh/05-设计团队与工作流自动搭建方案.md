# 设计团队与工作流自动搭建方案

## 目标

让 SueLr Studio 能像一个完整设计团队一样工作。

不是用户手动拼每个节点，而是用户描述目标，系统自动组织角色、拆任务、搭建工作流、执行生产、评审返工。

## Agent 角色类型

### 管理角色

```text
项目经理
  负责 Brief、任务拆解、审批节点、最终报告。

团队调度
  负责选择团队模板、分配任务、安排协作顺序。

知识运营
  负责检索、整理、写入知识。

运行复盘
  负责总结执行结果、失败原因、改进建议。
```

### 策略角色

```text
品牌策略
  负责定位、受众、价值主张、语气、竞品。

营销策略
  负责渠道、活动角度、转化目标。

内容策略
  负责内容栏目、发布形式、主题结构。
```

### 创意角色

```text
创意总监
  负责创意方向、整体审美、最终创意判断。

美术指导
  负责构图、色彩、风格、参考方向。

文案策划
  负责 slogan、标题、正文、社媒文案、视频脚本。

分镜师
  负责镜头顺序、画面描述、转场。
```

### 生产角色

```text
提示词工程
  把创意方向转成模型可执行提示词。

图片生产
  调用图片生成、图片编辑、图片比较。

视频生产
  调用视频生成、视频方向规划。

资产管理
  保存、命名、打包、索引产物。
```

### 工作流角色

```text
Workflow Architect
  根据需求设计工作流结构。

节点配置
  把工作流阶段映射到现有节点类型和参数。

工作流校验
  检查连接、输入、模型、输出。

失败诊断
  读取运行日志并给出修复建议。
```

### 评审角色

```text
质量评审
  检查可用性、清晰度、构图、明显缺陷。

品牌一致性评审
  检查是否符合品牌知识。

风险评审
  检查版权、敏感内容、夸大宣传、危险操作。
```

## 协作模式

### 串行生产

```text
Brief -> 策略 -> 创意 -> 工作流 -> 生产 -> 评审 -> 输出
```

适合稳定任务。

### 并行提案

```text
Brief
  -> 方向 A
  -> 方向 B
  -> 方向 C
  -> 创意总监评审
```

适合探索方向。

### 评审返工

```text
生产 -> 质量评审 -> 修改提示词或工作流 -> 再生产
```

适合提高图片/视频质量。

### 会议模式

多个角色围绕 Brief 讨论，项目经理总结决策。

这个模式更复杂，建议后期做。

## 自动搭建工作流规则

Workflow Architect 不直接写最终节点。

必须走：

```text
用户需求
  -> WorkflowIntent
  -> WorkflowDraft
  -> 编译器
  -> 校验报告
  -> 用户预览
  -> 用户确认
  -> 保存或执行
```

例子：

```text
需求：
  输入产品图和卖点，输出 6 张电商主图。

草案：
  输入：
    产品图
    卖点文案
  阶段：
    检索品牌规则
    扩写卖点
    生成提示词变体
    生成 6 张候选图
    评审候选图
    保存通过结果
```

编译后可能是：

```text
Image Input
Text Input
Prompt Helper / AI Chat
Image Gen x 6
Image Compare / Review
Save File
Output
```

## 默认审批规则

```text
知识检索：自动
创建工作流草案：自动
应用草案到画布：需要确认
保存工作流：需要确认
执行工作流：需要确认
图片/视频生成：默认需要确认
保存品牌/项目规则：需要确认
删除/覆盖：必须确认
```

## 每次团队运行的交付物

每次团队运行都应该输出：

- Brief 摘要
- 使用的团队和角色
- 任务计划
- 工作流草案或工作流 ID
- 生成资产
- 评审评分
- 返工记录
- 最终建议
- 知识写入摘要
