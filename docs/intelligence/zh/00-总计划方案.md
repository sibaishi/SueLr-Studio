# 总计划方案

## 一句话目标

把 SueLr Studio 做成一个本地优先的对话式 AI 工作系统。

用户不需要先理解工作流、节点、工具或团队模板。用户只需要在 Agent 窗口里说明想完成什么，Agent 负责理解需求、必要时追问、选择工具、执行工具、整理结果，并把可追溯记录折叠保留。

工作流搭建只是 Agent 的一个工具能力，不是 Agent 的产品形态。

## 产品方向调整

旧方向：

```text
用户需求
  -> 选择或组建设计团队
  -> 团队拆解任务
  -> 工作流助手生成草案
  -> 用户在工作流页面继续操作
```

新方向：

```text
用户需求
  -> 全局对话式 Agent
  -> Agent 窗口内选择 Planner 模型
  -> LLM planner 生成结构化计划
  -> Runtime 校验计划
  -> 调用受控工具
  -> 返回最终结果
  -> 工具记录折叠保存
```

因此，`AI 设计团队`、`工作流助手`、固定团队模板不再是当前主线。它们可以作为后续内部策略、专家模式或知识结构存在，但不作为第一版用户入口。

## 当前项目基础

新方向必须贴合 SueLr Studio 当前项目现状：

- Electron 41 桌面壳，`electron/main.cjs` 保持 CommonJS。
- React 19 + TypeScript + Vite 前端。
- Express 后端固定端口 `3001`。
- 工作流页面在 `src/domains/workflow/`。
- 全局 Agent 属于跨域功能，放在 `src/features/agent/`。
- 工作流节点定义在 `src/shared/workflow/node-definitions/`。
- 工作流执行继续走 `backend/src/modules/execution/` 和现有 engine。
- 模型 provider 配置继续复用现有设置体系。
- 生成文件 URL 继续使用 `/api/outputs/...` 和 `/api/assistant/files/...`。
- 本地 MVP 优先覆盖 `desktop` 和 `local-web`。
- 当前支持范围聚焦 `desktop` 和 `local-web`。

## 核心原则

### 1. Agent 是对话式工具调用者

Agent 的核心能力不是“会聊天”，也不是“会搭工作流”，而是：

- 理解用户任务。
- 判断是否需要追问。
- 检索知识。
- 选择工具。
- 调用工具。
- 汇总结果。
- 记录 trace。

### 2. LLM planner 是大脑，Runtime 是边界

LLM planner 负责理解和规划；代码负责校验、执行、存储和权限。

Planner 不能直接修改 React Flow 状态，不能绕过确认执行高成本操作，不能把未经校验的 JSON 写入工作流。

### 3. 工具必须受控

每个工具必须定义：

- id
- 输入 schema
- 输出 schema
- 副作用等级
- 是否需要用户确认
- trace 记录
- 错误处理

### 4. 模型来源由 Agent 窗口选择

Planner 模型不新增到全局设置项里。Agent 窗口内提供 Planner 模型选择，只能选择用户已显式启用的对话类模型。

如果没有可用对话模型，Agent 应提示用户先启用模型，而不是自动使用图像/视频模型或未启用模型。

## 总体架构

后端智能模块：

```text
backend/src/modules/intelligence/
  agent/              对话式 Agent 会话、计划、工具调度
  planner/            LLM planner 与结构化计划
  skills/             受控后端能力定义
  tools/              Agent 可调用工具适配层
  knowledge/          Studio Brain 知识库
  workflow-builder/   工作流意图、草案、编译、校验
  runtime/            run trace、工具调用记录、审批状态
  governance/         权限、副作用、确认、审计
```

前端入口：

```text
src/features/agent/       全局 Agent 窗口、模型选择、对话、结果、折叠工具记录
src/domains/workflow/     工作流画布与工具执行目标，不再承载独立工作流助手
src/domains/chat/         未来可复用 Agent 对话能力
src/features/settings/    只管理 provider 和模型启用，不新增固定 Planner 设置项
```

## 能力分层

```text
1. Agent UI
   对话输入、Planner 模型选择、结果展示、工具记录折叠。

2. LLM Planner
   读取用户需求、当前上下文、工具定义、节点知识，输出结构化计划。

3. Tool Runtime
   校验计划、执行工具、处理确认、写入 trace。

4. Studio Brain
   节点语义、工具规则、模型经验、用户偏好、历史成功案例、运行经验。

5. Workflow Tools
   创建、编辑、校验、应用、运行、诊断和总结工作流。

6. Production Tools
   图像、视频、文本、提示词、资产包、文件、结果检查。

7. Review & Learning
   结果复盘、失败诊断、知识沉淀、模板提升。
```

## 第一条落地闭环

第一条可测闭环选择：

```text
用户在 Agent 中输入需求
  -> 选择 Planner 模型
  -> LLM planner 理解任务
  -> 检索节点知识和工具定义
  -> 选择 workflow.createDraft 工具
  -> 生成工作流草案
  -> Runtime 校验
  -> Agent 展示最终结果和折叠工具记录
  -> 用户确认新建画布
```

这一条闭环最贴合当前项目能力，也能最快暴露节点语义、知识库和工具规划是否正确。

## 成功标准

本地 MVP 成功标准：

- 用户能在全局 Agent 窗口中发起任务。
- Agent 窗口能选择 Planner 模型。
- LLM planner 能基于工具定义和知识库生成结构化计划。
- 工具调用记录默认折叠，最终结果清晰展示。
- 工作流生成不再完全依赖本地硬编码规则。
- 工作流草案必须经过编译和校验后才能应用到画布。
- Agent 能逐步支持 `workflow.edit`、`workflow.applyDraft`、`workflow.execute`、`workflow.diagnose` 和结果总结。
- 图像、视频、文本、资产等能力可以作为工具继续接入。
- 经验能沉淀到知识库，但重要规则写入需要确认。
- 旧 Agent 和旧工作流助手不再承担主流程。
- `npm run check` 能通过。
