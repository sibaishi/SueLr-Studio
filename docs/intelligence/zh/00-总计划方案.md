# 总计划方案

## 一句话目标

把 SueLr Studio 做成一个本地优先的 AI 设计工作室操作系统。

不是只做一个聊天 Agent，也不是只加一个知识库，而是让系统具备完整的设计生产能力：

```text
理解需求
  -> 追问关键信息
  -> 组建设计团队
  -> 检索项目知识
  -> 生成项目计划
  -> 自动搭建工作流
  -> 用户确认
  -> 执行工作流和 Skills
  -> 评审结果
  -> 自动返工
  -> 输出资产包
  -> 沉淀知识和模板
```

## 当前项目基础

这个计划必须贴合 SueLr Studio 当前项目现状。

当前项目已经具备：

- Electron 41 桌面壳，`electron/main.cjs` 必须保持 CommonJS
- React 19 + TypeScript + Vite 前端
- Express 后端，固定端口 `3001`
- 工作流画布在 `src/domains/workflow/`
- 工作流节点定义在 `src/shared/workflow/node-definitions/`
- 工作流执行在 `backend/src/modules/execution/` 和 `backend/src/engine/`
- 模型与 provider 配置在 `src/shared/providers/` 和 `backend/src/platform/providers/`
- 设置页在 `src/features/settings/`
- 当前不成熟 Agent 体系在 `backend/src/modules/agent/`
- 运行时存储解析器在 `backend/src/platform/storage/`
- 生成文件 URL 使用 `/api/outputs/...` 和 `/api/assistant/files/...`

所以新系统不能脱离这些基础另起炉灶。

## 最终产品形态

最终 SueLr Studio 应该像一个 AI 设计公司。

用户可以输入：

```text
我要做一个新中式茶饮品牌，从品牌定位、主视觉、包装方向、电商详情页、小红书首发内容，到 15 秒广告视频都帮我做出来。
```

系统应该能够：

1. 追问品牌、受众、价格带、渠道、交付形式等必要信息
2. 生成品牌 Brief
3. 自动选择设计团队模板
4. 分配任务给不同角色
5. 检索品牌知识、项目知识、素材库、历史运行经验
6. 自动生成工作流草案
7. 让用户预览并确认
8. 执行图片、视频、文案、文件保存等生产流程
9. 由多个评审角色打分
10. 不合格时修改提示词、参数或工作流并返工
11. 输出最终资产包
12. 把成功流程、提示词、参数、失败经验写入知识库

## 总体架构

建议新建后端智能模块：

```text
backend/src/modules/intelligence/
  agents/             Agent 角色
  teams/              团队模板与调度
  skills/             可执行能力
  knowledge/          知识库
  workflow-builder/   工作流自动搭建
  planner/            项目计划与任务拆解
  runtime/            运行时
  review/             评审与返工
  telemetry/          运行轨迹
  governance/         权限、审批、策略
```

前端入口仍然遵守当前项目目录规则：

```text
src/domains/chat/        聊天、团队协作入口
src/domains/workflow/    工作流助手、草案预览、失败诊断
src/features/settings/   Agent、团队、Skills、知识库配置
src/shared/api/          共享 API 客户端
```

不要把领域组件放进 `src/components/`。

## 七层能力模型

```text
1. Studio Brain
   项目知识、品牌知识、素材索引、模型经验、运行经验、提示词库。

2. Team System
   多 Agent 团队模板、角色配置、协作模式、任务交接。

3. Project Manager
   需求解析、项目拆解、进度控制、审批点、最终汇报。

4. Workflow Architect
   根据需求自动规划、创建、修改、验证工作流。

5. Skill Runtime
   结构化可执行能力，如图片生成、视频生成、知识检索、工作流执行。

6. Asset Pipeline
   图片、视频、文案、音频、文件、资产包生产。

7. Review Loop
   质量评审、品牌一致性评审、风险检查、返工、复盘。
```

## 核心工程原则

模型负责理解、规划、建议。

代码负责校验、编译、执行、存储、权限。

尤其是自动搭建工作流时，不能让模型直接写最终 React Flow 节点并落库，而应该走中间协议：

```text
用户需求
  -> WorkflowIntent
  -> WorkflowDraft
  -> WorkflowCompiler
  -> WorkflowValidator
  -> 合法工作流 JSON
  -> 前端预览
  -> 用户确认
  -> 保存或执行
```

这样可以避免模型乱连节点、破坏工作流结构，且不违反 React Flow 状态所有权规则。

## 设计方向覆盖

长期应覆盖：

- 品牌定位与品牌视觉
- 平面海报、Banner、封面、活动视觉
- 电商主图、详情页、卖点图
- 包装设计与系列化视觉
- UI/UX 页面、仪表盘、组件规范
- 小红书、抖音、微博、B站等社媒内容
- 视频脚本、分镜、镜头语言、短视频生成
- IP 角色、表情、场景、周边视觉
- 空间、展陈、快闪店、导视方向
- 3D 与动效概念
- 提示词工程与模型生产流水线
- 设计运营、素材管理、知识管理

第一条落地闭环建议选择：

```text
品牌/电商视觉需求
  -> 自动搭建图片生成工作流
  -> 执行
  -> 评审
  -> 返工
  -> 沉淀模板和知识
```

这条路径最贴合当前项目已有能力。

## 成功标准

总计划成功的标准：

- 用户可以用自然语言描述设计目标
- 系统能自动拆解成设计任务
- 系统能组建设计团队
- 系统能生成工作流草案
- 用户能预览并确认
- 工作流通过现有执行引擎运行
- 结果能被评审和返工
- 成功结果能打包输出
- 经验能沉淀到知识库
- 当前旧 Agent 体系被平稳替换
- `npm run check` 能通过
