# 分阶段验收与总验收计划

## 验收原则

这个系统不能按“模型看起来会回答”来验收。

必须按真实生产闭环验收：

```text
需求是否能拆解
知识是否能检索
团队是否能协作
工作流是否能生成
用户是否能确认
执行是否走现有引擎
结果是否可追踪
失败是否能诊断
经验是否能沉淀
旧 Agent 是否能替换
```

## 阶段 0 验收

命令：

```bash
npm run check:docs
npm run check:encoding
```

人工验收：

- 公开文档已落地
- docs 门禁允许 intelligence 文档
- 没有把临时私有笔记放进 docs
- 旧 Agent 的替换方向明确

## 阶段 1 验收

命令：

```bash
npm run typecheck
npm run test --prefix backend
npm run check:encoding
```

验收项：

- `/api/intelligence/skills` 能列出 Skills
- `/api/intelligence/runs` 有 Zod 校验
- 错误响应是 `{ error, code, status }`
- 只读 Skill 不会修改数据
- run trace 可创建、保存、读取
- 旧 `/api/agent` 不受影响

## 阶段 2 验收

命令：

```bash
npm run typecheck
npm run test:unit
npm run test --prefix backend
```

验收案例：

- 商品图工作流
- 品牌主视觉探索工作流
- 社媒图片批量生成工作流

验收项：

- 能生成 WorkflowDraft
- 能编译成合法工作流 JSON
- 能检查缺失模型、缺失输入、非法连接
- 前端能预览
- 用户取消时不修改当前画布
- React Flow 状态不进入 Zustand

## 阶段 3 验收

命令：

```bash
npm run typecheck
npm run test --prefix backend
npm run test:unit
```

验收项：

- 用户确认后才能执行
- 执行走 `ExecutionService`
- 生成文件 URL 符合 `/api/outputs/...`
- 失败能生成诊断报告
- 成功能生成资产清单
- SSE 断开不等于取消
- 取消仍走 cancel endpoint
- 知识库不能静默选择工作流或输入

## 阶段 4 验收

命令：

```bash
npm run typecheck
npm run test --prefix backend
npm run check:encoding
```

验收项：

- 每类知识有 schema
- 知识记录有来源、作用域、时间、置信度或证据
- 搜索结果返回类型和来源
- 运行经验必须关联真实 run trace
- 品牌规则和项目规则写入前需要确认
- 旧 memory 可以迁移

## 阶段 5 验收

命令：

```bash
npm run typecheck
npm run test:unit
npm run test --prefix backend
```

验收项：

- 项目经理能从 Brief 拆任务
- 品牌视觉团队能输出策略、创意、工作流草案、评审结果
- 工作流工程团队能创建或诊断工作流
- 质检角色能给出明确评分和修改建议
- 每个角色输出能追溯

## 阶段 6 验收

命令：

```bash
npm run typecheck
```

验收项：

## 总验收计划

最终总验收用一条完整用户路径：

```text
用户输入：
  我要做一套电商新品发布视觉，包含主图、详情页首屏、小红书首发图和 15 秒短视频方向。

系统流程：
  1. 追问必要信息
  2. 生成 Brief
  3. 选择团队
  4. 拆任务
  5. 检索品牌和项目知识
  6. 生成工作流草案
  7. 用户确认
  8. 执行工作流
  9. 生成图片/文案/视频方向
  10. 质检评分
  11. 自动返工一次
  12. 输出资产包
  13. 写入运行经验和提示词库
```

总验收必须满足：

- 全链路可追踪
- 用户可以在关键点中止
- 高成本操作有确认
- 输出资产可打开
- 知识写入有来源
- 旧 Agent 体系不再承担主流程
- `npm run check` 通过
