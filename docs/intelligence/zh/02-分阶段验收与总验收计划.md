# 分阶段验收与总验收计划

## 验收原则

这个系统不能按“模型看起来会回答”来验收。

必须按真实生产闭环验收：

```text
需求是否能拆解
知识是否能检索
团队是否能协作
工作流是否能生成
用户是否能确认
执行是否走现有引擎
结果是否可追踪
失败是否能诊断
经验是否能沉淀
旧 Agent 是否能替换
```

第一总验收目标是本地闭环：`desktop` 和 `local-web` 必须先完成 Agent + Skills + 知识库 + 工作流生成 + 执行 + 评审 + 资产包 + 知识沉淀。

`server-web`、多用户共享知识库、按用户 provider 消耗、三端同步不是本地 MVP 通过条件。它们保留为本地总验收通过后的服务器迁移验收。

- 公开文档已落地

## 阶段 1 验收

命令：

```bash

npm run test --prefix backend
npm run check:encoding
```

验收项：

- `/api/intelligence/skills` 能列出 Skills
- `/api/intelligence/runs` 有 Zod 校验

- run trace 可创建、保存、读取
- 旧 `/api/agent` 不受影响
- 不依赖服务器端用户隔离或同步能力

## 本地 MVP 总验收计划

本地总验收用一条完整用户路径：

```text
用户输入：
  我要做一套电商新品发布视觉，包含主图、详情页首屏、小红书首发图和 15 秒短视频方向。

系统流程：
  1. 追问必要信息
  2. 生成 Brief
  3. 选择团队
  4. 拆任务
  5. 检索品牌和项目知识
  6. 生成工作流草案
  7. 用户确认
  8. 执行工作流
  9. 生成图片/文案/视频方向
  10. 质检评分
  11. 自动返工一次
  12. 输出资产包
  13. 写入运行经验和提示词库
```

总验收必须满足：

- 全链路可追踪
- 用户可以在关键点中止
- 高成本操作有确认
- 输出资产可打开
- 知识写入有来源
- 旧 Agent 体系不再承担主流程
- `npm run check` 通过
- 在 `desktop` 和 `local-web` 本地形态下通过人工冒烟

`server-web` 不作为本地 MVP 通过条件。本地验收通过后，才进入阶段 9 到阶段 12。

## 完整项目总验收

完整项目总验收 = 本地 MVP 总验收通过 + 阶段 9 到阶段 12 服务器迁移验收全部通过。
