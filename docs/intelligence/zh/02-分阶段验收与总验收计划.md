# 分阶段验收与总验收计划

## 验收原则

新 Agent 不能按“模型看起来会回答”验收，必须按真实工具闭环验收。

核心验收链路：

```text
用户能否在全局 Agent 中提出需求
Planner 模型是否由用户在 Agent 窗口选择
LLM planner 是否能生成结构化计划
计划是否经过 Runtime 校验
工具是否按计划执行
高成本/副作用操作是否需要确认
最终结果是否清晰展示
工具记录是否默认折叠且可追溯
经验是否能进入知识库
旧工作流助手是否退出主流程
```

本地 MVP 只要求 `desktop` 和 `local-web` 通过。`server-web`、多用户共享知识库、同步和公共审核属于后续阶段。

## 阶段 0 验收：方向重置

命令：

```bash
npm run check:encoding
```

人工验收：

- 文档明确新方向是全局对话式 Agent。
- 文档不再把“设计团队”作为第一版主入口。
- 文档明确工作流只是 Agent 工具之一。
- 文档明确 Planner 模型在 Agent 窗口内选择。

## 阶段 1 验收：全局 Agent UI 基线

命令：

```bash
npm run typecheck
npm run check:encoding
npm run build
```

人工验收：

- 点击 `AI 助手` 打开的是全局 `AI Agent` 窗口。
- 不出现独立 `AI 工作流助手` 面板。
- 不出现 `AI 设计团队` 主标题。
- 工具调用记录默认折叠。
- 最终结果和工具记录分离。

## 阶段 2 验收：Agent 窗口内 Planner 模型选择

命令：

```bash
npm run typecheck
npm run test:unit
npm run check:encoding
```

验收项：

- Agent 窗口能列出已启用的对话模型。
- 可以切换 Planner 模型。
- 最近选择能本地保留。
- 没有对话模型时，Agent 明确提示需要启用对话模型。
- 不会自动选用图像/视频模型。
- 不会使用未显式启用的发现模型。

## 阶段 3 验收：LLM Planner MVP

命令：

```bash
npm run typecheck
npm run test --prefix backend
npm run check:encoding
```

验收项：

- `/api/intelligence/agent/plans` 有 Zod 输入校验。
- 错误响应保持 `{ error, code, status }`。
- Planner 输出通过结构化 schema 校验。
- Planner 输出的工具 id 必须存在。
- Planner 不能直接修改工作流画布。
- Planner 能在信息不足时返回追问。

关键人工案例：

```text
帮我做一个分镜图生成流程，用文本脚本生成 8 张连续分镜图。
```

验收：

- 不直接选择视频生成节点。
- 能识别分镜图是图像序列任务。
- 能合理选择文本输入、文本拆分/逐项、图像生成、保存/输出等结构。

## 阶段 4 验收：Tool Runtime 与工作流工具化

命令：

```bash
npm run typecheck
npm run test:unit
npm run test --prefix backend
```

验收项：

- `workflow.build` 能生成工作流草案。
- `workflow.validate` 能检查草案合法性。
- `workflow.applyDraft` 必须用户确认。
- `workflow.run` 必须用户确认。
- 工具调用写入 trace。
- 前端能展示最终结果和折叠工具记录。
- React Flow 状态不进入 Zustand。

## 阶段 5 验收：节点语义知识与规划质量

命令：

```bash
npm run typecheck
npm run test --prefix backend
npm run check:encoding
```

验收案例：

- 分镜图生成。
- 电商主图批量生成。
- 文本输入直连输出展示。
- 图片输入直连保存/输出。
- 多输入合并。
- 逐项运行。

验收项：

- 节点语义知识能被 planner 检索。
- 辅助提示词不会在不需要时强行出现。
- 分镜图任务不会误用视频生成节点。
- 逐项运行被理解为按输入项传递/执行，而不是只取第一个非空输入。
- 合并节点被理解为聚合多个输入，而不是替代执行顺序。
- 输出节点与保存文件节点的区别清晰。

## 本地 MVP 总验收

完整用户路径：

```text
用户在 Agent 中输入：
  我需要一套新品电商视觉方案，包含主图、详情页首屏、小红书首发图和 15 秒短视频方向。

系统流程：
  1. Agent 判断是否需要追问。
  2. 用户在 Agent 窗口选择 Planner 模型。
  3. LLM planner 生成结构化计划。
  4. Runtime 校验工具调用。
  5. Agent 调用工作流、图像、文本、视频或知识工具。
  6. 用户确认高成本或有副作用的动作。
  7. 系统输出最终结果、产物和报告。
  8. 工具记录折叠保留。
  9. 成功经验可确认写入知识库。
```

必须满足：

- 全链路可追踪。
- 用户能在关键点中止。
- 高成本操作有确认。
- 输出产物可打开。
- 知识写入有来源。
- 旧工作流助手不再承担主流程。
- `npm run check` 通过。

`server-web` 不作为本地 MVP 通过条件。本地 MVP 通过后，才进入服务器迁移阶段。
