# Agent 实测问题反馈表

## 这个表是做什么的

本表用于记录在前端实际使用对话式 Agent、LLM Architect、工作流生成/编辑/执行能力时发现的问题。

后续如果更换对话、切换开发会话或继续排查，请先阅读本表。这里记录的是用户真实测试中出现的偏差，用于继续调整 Agent 的节点理解、工具选择、LLM planner 提示词、DSL 校验、工作流参数填充和前端诊断展示。

重点记录“用户想让 Agent 完成什么复杂工作”和“实际生成/执行结果哪里不符合预期”。不要只写一句“效果不好”，要尽量留下可复现输入和具体偏差。

## 填写说明

- 一条问题填一行。
- “用户原始需求”尽量粘贴完整输入。
- “期望结果”写你认为 Agent 应该搭出的工作流结构、节点、参数或最终产物。
- “实际结果”写前端看到的结果，包括是否生成了错误节点、漏了链路、参数没填、回退本地编排等。
- “诊断信息”如果前端显示了 LLM Architect、自动修复、回退原因、validation issues，请原样填入。
- “优先级”建议用 P0/P1/P2：P0 阻断使用，P1 明显错误，P2 体验或质量改进。

## 实测检查项

后续在前端实际使用 Agent 时，可以按下面清单检查生成结果。发现偏差后，把对应现象填到“问题记录”。

| 检查项 | 应重点观察什么 |
| --- | --- |
| 生成入口 | 是否从 Agent 窗口输入需求并成功生成工作流草案 |
| 需求理解 | 生成结果是否真的回应了用户原始需求，而不是只套用通用模板 |
| 工作流结构 | 复杂需求是否被拆成多链路，而不是只有一条简单链路 |
| 多 AI 协作 | 是否按职责使用多个 AI 节点，例如需求拆解、文案生成、分镜规划、质检总结 |
| 逐项运行 | 批量/分镜/多输入任务是否使用 `textSplit + iterateRun` 或 `iterateImageRun` |
| 文本拆分 | `textSplit` 是否显式设置 `separator` 和 `outputCount` |
| 上游输出格式 | 连接到 `textSplit` 的上游 `aiChat.systemPrompt` 是否明确要求按同一分隔符输出，例如“每行一个片段，不要输出解释” |
| 参数填充 | `aiChat.systemPrompt`、`imageGen.ratio/resolution/n/output_format`、`videoGen.duration/resolution/ratio`、`saveFile.filenamePrefix` 等是否按需求设置 |
| 节点选择 | 是否误用节点，例如分镜图错误使用 `videoGen`、普通提示词错误使用 `promptHelper` |
| 输出链路 | 最终产物是否经过 `saveFile` 并汇总到 `output` |
| 结果可用性 | 打开画布后是否能继续编辑，节点和连线是否可读、可运行 |
| 执行反馈 | 运行后是否能捕获最终产物，而不是缩略图、中间产物或空输出 |

## 问题类型参考

| 类型 | 说明 |
| --- | --- |
| 工作流结构 | 链路太简单、没有多链路、缺少分支、没有输出汇总、错误使用视频/图片/文本链路 |
| 节点语义 | 选错节点、误用 `promptHelper`、误解逐项运行/合并节点/输出节点 |
| 参数填充 | 没设置 `systemPrompt`、`ratio`、`resolution`、`n`、`duration`、`filenamePrefix`、`outputCount` 等 |
| 工具调用 | Agent 没有调用应调用的工作流工具、知识库工具、文件工具或执行工具 |
| 正常对话 | 用户只是想聊天/解释/分析，但 Agent 只会调用工具或强行生成工作流 |
| 执行结果 | 工作流能生成但运行失败、结果没捕获、产物引用错误、输出不是最终产物 |
| UI 展示 | 前端看不出是否用了 LLM、是否自动修复、为什么回退、结果在哪里查看 |

## 后续处理约定

处理这些问题时，优先按以下顺序排查：

1. 是否是节点知识库/节点语义描述不准确。
2. 是否是 LLM Architect prompt 没约束清楚。
3. 是否是 DSL 校验没有拦住低质量或错误结构。
4. 是否是编译器没有正确归一化节点参数或动态端口。
5. 是否是前端诊断展示不足，导致用户无法判断发生了什么。
6. 是否是 Agent 工具边界设计问题，比如正常对话和工具调用没有分流。
