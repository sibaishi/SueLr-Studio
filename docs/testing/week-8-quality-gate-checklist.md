## 手工冒烟步骤

### 1. 节点基础编辑

- [x] 新建两个不同类型的节点，确认节点能落到画布且默认选中最新节点
- [x] 复制其中一个节点，确认复制结果发生位移，且不会覆盖原节点
- [x] 删除复制出的节点，确认节点消失且未留下异常选中态
- [x] 预期结果：节点增删复制过程无报错，画布状态与选中态一致

### 2. 连线与 merge 尺寸联动

- [x] 准备一个 `merge` 类节点和至少两个上游节点
- [x] 依次给 merge 节点增加输入连线，确认 merge 节点尺寸会随输入数量调整
- [x] 替换某一条输入连线，确认旧连线被替换后布局仍正常
- [x] 删除其中一条连线，确认 merge 节点尺寸可回收或保持在合理最小尺寸
- [x] 预期结果：连线增删替换后无重叠、无异常尺寸、无控制台报错

### 3. 分组、解组与释放

- [x] 选择两个及以上普通节点创建分组，确认生成 group 且节点被正确收入组内
- [x] 拖动组或组内节点，确认节点不会越出非法区域
- [x] 执行解组，确认节点回到根层级且位置基本保持合理
- [x] 再次分组后执行“释放分组内节点”，确认被释放节点回到根层级且位置可见
- [x] 预期结果：分组链路中无节点丢失、无错位到画布外、无异常 parent 关系残留

### 4. 草稿持久化

- [x] 在当前工作流中保留若干节点和连线
- [x] 触发一次本地草稿保存（如存在自动保存则等待其完成）
- [x] 刷新页面或重新打开应用
- [x] 确认工作流草稿被恢复，节点、连线、名称与刷新前一致
- [x] 预期结果：草稿恢复成功，且不会残留旧执行日志或异常执行态

### 5. 项目模型分组刷新

- [x] 打开项目模型或设置面板，调整一次项目模型配置
- [x] 返回工作流节点配置区域，查看模型下拉分组是否同步刷新
- [x] 至少验证 `chat` / `image` 两类模型分组之一发生预期变化
- [x] 如支持移除模型，再执行一次移除并确认前端分组同步更新
- [x] 预期结果：模型列表刷新及时，分组正确，无旧数据残留
